# 政策材料接入

把政策文件放进 `materials/`，或直接在页面里上传 / 粘贴，服务端会用同一套规则解析、
抽取字段并保留原文定位。本文件说明五种接入方式与能力边界。

## 一、五种接入方式

| 方式 | 适用格式 | 怎么做 |
|---|---|---|
| **A. 按产业自动获取**（推荐） | 官网在线文件 | 打开 `/policy` → 输入公司名 → 点「获取政策与补贴公告」。按主体行业与注册地，在已接入的政策站点检索并抓取，抓回即抽字段并给原文链接 |
| **B. 目录扫描** | `.pdf` `.docx` `.txt` `.md` `.html` | 文件放 `materials/` → 在 `/policy` 点「重新扫描 materials/」 |
| **C. 页面内拖入** | 同上 | 在 `/policy` 把文件拖进「材料来源」区域，上传后服务端即时解析 |
| **D. 粘贴全文** | 任意（含扫描件的识别结果） | `/policy` 点「粘贴全文解析」，粘贴正文后解析 |
| **E. 命令行** | 同上 | `python -m mingjian policy --dir materials --csv output/policy.csv`，或 `python -m mingjian gov 某某企业` |

B—E 走同一个解析模块 `mingjian/services/policy.py`；A 先取回官网原文，再交给同一模块解析。
五种方式的结果口径一致。

## 二、目录约定

```text
materials/                 政策材料投放目录（真实材料不入库）
├── .gitkeep               占位文件
├── 政策公告/               建议按类型分子目录，子目录会被递归扫描
└── ...
```

- 目录为空时页面就是空态，不预置样例。
- 扫描会跳过隐藏文件与 `README*`，避免把说明文件当成待解析公告。
- 需要长期保存的材料建议放独立目录，用 `--dir` 指定。

## 三、批处理

```bash
# 解析本目录全部文件
python -m mingjian policy --dir materials

# 同时导出 CSV，便于交给业务方复核
python -m mingjian policy --dir materials --csv output/policy.csv

# 材料很多时只看前 10 条
python -m mingjian policy --dir materials --limit 10
```

网页入口不需要命令：`/policy` 打开时自动扫描 `materials/`，顶部显示已扫描与跳过的份数。

## 四、几条设计约束（有意为之，不是缺陷）

1. **抽不到就留空，不猜。** 字段缺失时单元格显示 `—`，并在异常清单里说明原因
   （例如「全文中未出现截止类表述」）。
2. **区间值不收敛。** 支持标准写成「10%—15%，由各市确定」时，置信度降到 0.61
   并自动转人工复核，不强行取一个数。
3. **单份失败不阻断批次。** 扫描件因无文本层解析失败只影响那一份，其余正常出结果，
   进异常清单并给补材料建议。
4. **非公告文本会被判失败。** 会议纪要、合同、内部通知等跑进来会得到
   「未识别到任何关键字段」——这是正确行为，不要为了让它「有结果」而放宽规则。
5. **人工确认必须留痕。** `/policy` 里改过的每个字段都会写入审计表
   （谁、何时、改了哪个字段、改前改后），可在「审计记录」里查。

## 五、能力边界

- PDF 需要文本层。**扫描件、图片型 PDF 抽不到内容**（无 OCR），会判失败并提示补
  300dpi 以上可编辑版本。
- `.doc`（旧版二进制）不支持，需另存为 `.docx`。
- 复杂合并单元格的表格，字段抽取可能错位，需人工复核。
- 抽取规则按当前接入站点的政策公告常见表述编写；新增来源或文风差异时
  可能需要补充规则，改 `mingjian/services/policy.py` 里的同名函数即可，网页与命令行同时生效。
