# 数据来源

本文列出系统实际访问的数据源、用途、失败模式与扩展方式。
合规与免责条款见 [../DISCLAIMER.md](../DISCLAIMER.md)。

## 一、来源清单

| 来源 | 用途 | 入口 | 失败时会怎样 |
|---|---|---|---|
| 巨潮资讯 | 实体解析（代码 / orgId / 全称）、公告列表、公告 PDF | `infra/sources/cninfo.py` | 实体解析失败则整次运行失败并提示；公告失败则该路材料为空，记入缺口 |
| 东方财富 | 公司档案、主营构成、定期报告指标、资讯检索 | `infra/sources/eastmoney.py` | 档案缺失时用巨潮字段兜底；指标取不到则专题不出点；资讯失败或风控时回退百度资讯 |
| 百度资讯 | 东方财富资讯检索失败时的回退，只取搜索结果首屏 | `infra/sources/baidu.py` | 命中安全验证或页面结构变化记失败，不重试；主源正常空结果时不触发回退 |
| 企业工商登记（可配置） | 企业检索、信用代码、法人、注册资本、经营状态、注册地址、经营范围、官网 | `infra/registry.py`；端点与密钥在设置页填写 | 未配置则不启用；超时或上游拒绝时只降级，原因随搜索结果返回 |
| 工业和信息化部 | 产业政策、专项资金等公告 | `services/govpolicy.py` | 检索失败时返回空结果与原因，不编造条目 |
| 省级工信主管部门（31 个） | 地方政策与补贴公告 | `services/govpolicy.py` 的 `PROVINCE_SITES` | 站点不可达记入 `data/prov_health.json`，页面提示「已知取不到」 |
| 用户上传材料 | 政策文件（pdf / docx / txt / md / html） | `services/policy.py` | 单份失败只影响该份，进异常清单；扫描件因无文本层判失败 |

## 二、调用约定

- 所有请求经 `core/net.py`：统一超时、有限重试、同域最小间隔（`host_interval`，默认 0.45 秒）。
- 不包含验证码识别、登录态伪造、代理轮换等绕过访问控制的手段。
- JSONP 回调名由上游决定（可能是 `cb(...)`，也可能换成 `jQuery...(...)`），只校验“函数名(JSON)”，不绑定具体名字。
- 上游可能返回 HTTP 200 但只给 `passportWeb`（股民资料）、没有文章列表；这属于风控失败，记 `error`，不能当成“没有资讯”。
- 回退只在主源**失败**时触发；主源正常返回空结果不换源，避免同一查询在不同源之间悄悄换口径。回退命中时留痕 `via=baidu`，并保留 `fallback_from` 说明主源失败原因。
- 请求失败按「单份失败不阻断整批」处理：记原因、保留链接、继续下一份。
- 抓取结果落 `documents` 表并标注证据等级：
  - `full`：拿到正文（公告 PDF 文本层或资讯正文）
  - `snippet` / `title`：只有摘要或标题（图片型 PDF、正文抓取失败）
- 原文只用于本地解析与引用，报告与导出中保留原始 URL。

## 三、省级站点健康

- `PROVINCE_SITES` 收录 31 个省级工信主管部门站点，`CITY_PROV` 负责城市到省份的归一。
- 每次取数后记录该省最近一次可用性到 `data/prov_health.json`。
- 实测常有 1—3 个站点不可达（近期为甘肃、海南、安徽），属于上游波动，不是程序缺陷。
- 页面与日志会区分两种「没有结果」：
  - **站点不可达**：网络层失败，建议稍后重试或人工补材料
  - **确实没有相关政策**：站点可达但没有匹配条目
- 部分省份的政策专栏为 JS 渲染，列表页拿不到正文时需人工放入 `materials/`。

## 四、企业工商登记

**官方没有面向公众的开放 API。** 国家企业信用信息公示系统（gsxt.gov.cn）只提供
网页查询且带人机验证，不提供机读接口；抓取它既不稳定也不合规。要覆盖全部合法
登记企业，稳定路径是使用商业数据服务的授权接口（天眼查、企查查、爱企查、启信宝，
或云市场上的同类商品），由服务商同步工商登记数据。

接入步骤：

1. 设置页「工商数据源」新增接口，选择预设或自定义；
2. 填端点、请求路径、鉴权方式与 API Key（企查查还需 Secret）；
3. 「测试连接」核对结果路径与字段映射，返回的条目与命中字段会列出来；
4. 保存即启用，公司搜索与监测对象搜索立即使用这一路。

边界：

- 接口按次计费。命中过的企业写入 `companies` 表，同一关键词在进程内缓存 300 秒；
  下次搜索先查本地，不再消耗额度。
- 字段映射可改：预设只提供接入形态，厂商调整响应结构时在「字段映射」里改路径即可，
  不必改代码。
- 未配置、停用或上游失败时，搜索退回证券主体库、本地档案与资讯线索；失败原因
  写入搜索响应的 `notes`，页面仍可手动建档。
- 密钥只落库，接口只回传尾号；启用、修改与删除记审计，不记明文。
- 官网随检索结果写入 `companies.website`，字段映射里提供「官网」一项；上市公司补充自东财
  公开档案，非上市企业取不到时可在监测对象编辑弹窗手填。列表只渲染通过校验的
  http/https 地址，点击新窗口打开。
- 仅接入已获授权的正式接口。系统不包含验证码识别、登录态伪造或代理轮换。

## 五、新增一个数据源

1. 在 `infra/sources/` 新建模块，只做两件事：请求与归一化。
2. 输出统一的文档形状：

```python
{
    "id": "D01",                 # 本次运行内唯一
    "kind": "announcement",      # announcement / news / web
    "title": "...",
    "url": "https://...",        # 必须保留，供回溯
    "source": "巨潮资讯",
    "published_at": "2026-11-20",
    "body": "...",               # 可为空，空则证据等级降级
    "evidence_level": "full",    # full / snippet / title
}
```

3. 不要在这里做事件分类、置信度或判断——这些属于 `services/`。
4. 失败要能降级：返回空列表并说明原因，不要向上抛异常打断整批。
5. 在 `tools/selftest_all.py` 里为归一化逻辑加断言（可用固定样本，不联网）。

## 六、与数据源相关的配置

| 配置 | 默认 | 作用 |
|---|---|---|
| `days` | 30 | 公告与资讯回溯天数 |
| `max_ann` / `max_news` | 40 / 45 | 每路材料条数上限 |
| `max_fetch` | 12 | 正文抓取条数上限，控制耗时 |
| `news_pages` | 3 | 资讯首路（公司名查询）翻页数 |
| `timeout` / `retries` | 15s / 2 | 单请求超时与重试 |
| `host_interval` | 0.45s | 同域最小请求间隔 |
| `registry`（设置页） | 未配置 | 工商接口的端点、鉴权、字段映射与超时；落 `settings` 表 |

环境变量前缀 `MINGJIAN_`，旧 `AGENT_` 前缀兼容。完整清单见 `config.example.json`。
