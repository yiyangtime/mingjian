# 方法论与判定规则

本文说明「事实怎么来、置信度怎么算、报告怎么组织」。这是项目的核心资产，
改动这里等于改产品语义，必须同步测试与文档。

## 一、七步流水线

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 1 实体解析 | 公司名 → 实体档案（orgId、全称、行业、主营、注册地） | `entities` |
| 2 多源采集 | 近 N 天公告 + 按公司名与检索词（可版本化）检索资讯，按主体相关度过滤；主源失败时回退备用资讯首屏 | 文档清单 + 每路召回与状态 + 被拒候选留痕 + 公告覆盖对照 |
| 3 正文解析 | 下载公告 PDF 还原中文、抓资讯正文；记录证据等级 | `documents.evidence_level` |
| 4 事实抽取 | 事件分类、金额与日期抽取、主体核验、证据句定位、置信度、跨源合并 | `facts` |
| 5 变化比对 | 与同一公司上一份快照比较：新增 / 升温 / 本轮未见 | 差异视图 |
| 6 报告成稿 | 八节结构，判断逐条挂事实编号 | Markdown / CSV |
| 7 留痕入库 | 事实、来源、快照、审计全部落库 | 数据库（默认 SQLite） |

第 1–4 步各存检查点；取消与失败发生在步骤边界。

## 二、事实模型

一条事实至少包含：

| 字段 | 含义 | 约束 |
|---|---|---|
| `type` | 事件维度 | capacity / order / product / price / capital / finance / policy / personnel / other |
| `statement` | 事实陈述 | 必须能独立读懂，不含推测 |
| `evidence_quote` | 证据句 | 原文中的一句话；取不到时退回标题并降置信度 |
| `doc_id` + `url` | 来源 | 必须有，供逐条回溯 |
| `amount` / `event_date` | 金额与日期 | 抽不到就留空，不猜 |
| `confidence` | 置信度 | 规则计算，取值 0.30—0.98 |
| `corroboration` | 佐证源数 | 跨源合并后累加 |
| `conflict` / `conflict_note` | 口径冲突 | 多源金额/规模不一致时记条数与说明 |

**硬约束**：没有证据句不产事实；缺失字段留空；事实与判断在结构上分离。

## 三、置信度

```text
置信度 = 证据等级基线
        + 0.04 × 事件判定强度（0—1）
        + 0.03（含金额）
        + 0.02（公告全文且正文超 300 字）
        + 0.015—0.02 ×（多源佐证数 - 1）
        - 0.06 ×（口径冲突数）
        - 0.12（归不进事件类型）
        - 0.06（证据句退回标题）
```

证据等级基线：

| 等级 | 含义 | 基线 |
|---|---|---|
| `full` | 公告全文（PDF 文本层） | 0.90 |
| `full` | 资讯正文 | 0.72 |
| `snippet` / `title` | 公告仅有摘要或标题 | 0.70 |
| `snippet` / `title` | 资讯仅有摘要或标题 | 0.55 |
| 其它 | 非公告、非资讯材料 | 0.52 |

取值限定在 0.30—0.98。**低于 0.45 不进事实区，只进「待验证与数据缺口」。**

同一事件被多家报道时自动合并：数字重合度用于识别「同一件事两种说法」，
合并后保留全部来源并累加佐证数。金额或规模口径不一致时不加佐证分，反而扣 0.06，
冲突说明随事实落库，报告事实行与「待验证与数据缺口」都会标出。

## 四、判断保真与留痕

判断段的每个字都必须是可复核的：模型只允许改写语气，不允许改数字、单位与引用。
送进模型的事实清单只装被判断引用的事实，未被引用的不进 prompt；判断越多、事实越多时，
输入 token 只随引用数增长，引用事实也不会因上下文预算截断而丢失。

| 校验 | 规则 | 失败处理 |
|---|---|---|
| 引用 | 只能引用真实事实编号，且与被改写的那条规则判断引用集合一致（不能把 F01 的依据挪给 F02） | 丢弃该条 |
| 数字与单位 | 金额/规模/百分比必须能在被引用事实或原判断中找到；中文数字先归一（八亿元 = 8亿元 = 80000万元，五成 = 50%，百分之五 = 5%）；单位不同按改事实处理 | 丢弃该条 |
| 否定与方向 | 「尚未 / 并未」不得被改掉或凭空新增；「上升 / 下降」不得与原判断相反，也不得引入事实里没有的方向 | 丢弃该条 |
| 整句与子句 | 与引用事实的字符二元组重合度低于 10%，或任一子句与原判断/引用事实完全对不上 | 丢弃该条 |

任一判断被拦，**整批回退规则判断**，不做部分采用：部分采用会让读者无法把改写句
与原判断一一对应，留痕也失去意义。拦截原因写进运行日志与判断留痕。

每轮运行都会把留痕写入 `runs.judgments` 与 `output/judgments_<run_id>.json`，内容包括
`rule`（规则判断原文）、`final`（最终采用的判断）、`rejected`（被拦截的改写句与原因）、
`raw`（模型原始输出截断）与 `model`（未配置模型时为 `rule-engine`）。报告首页标注
「规则生成 N 条 / 模型改写 N 条 / 校验拦截 N 条」，每条判断标注来源；运行统计写入
`judgments_rule`、`judgments_llm`、`judgments_rejected`。企业洞察页的「判断留痕」
逐条对照规则版与采用版，接口为 `/api/company/judgments/<run_id>`。

### 多源口径冲突

同一事件被多家报道时，先合并再判断，但“多家报道”不等于“互相印证”：

- 按指标族比对：金额只和金额比，产能只和产能比，占比只和占比比，不是全句数字集合求交；
- 同一指标族取值不一致 → 记为口径冲突，保留冲突说明；冲突来源**不计入佐证数**，
  反而扣 0.06，并在事实行与缺口清单中显式标出；
- 金额单位不同但等值（如 5 亿元与 50000 万元）不算冲突；
- 冲突导致置信度跌破 0.45 的事实仍会在缺口清单出现，不会连冲突一起消失；
- 只比对可量化口径；跨指标（产能 vs 产量）与「谁更强」这类定性分歧仍需人工判断。

## 五、企业洞察报告（八节）

1. **公司速览**：代码 / 全称 / 行业 / 主营 / 注册地。不写股价与市值。
2. **本期要点**：本批最重要的几条事实，带编号。
3. **事实清单**：类型 / 金额 / 日期 / 置信度 / 证据句 / 原文链接。
4. **变化对比**：相对上一份快照的新增、升温、本轮未见；首次运行明确写「无历史基线」。
5. **判断**：每条挂 `F01/F02…` 与置信度，可逐条反驳。
6. **建议动作**：基于判断给出下一步核验或跟进方向，不代替决策。
7. **待验证与数据缺口**：取不到的材料、低于阈值的线索、需要的内部数据。
8. **方法与口径**：证据等级、置信度构成、比对规则、数据源与时间窗口。

### 推送摘要与正文的边界（`services/report.push_digest`）

机器人消息只是提醒，不是报告本体：摘要只含标题、事实数与高置信 / 口径冲突计数、
前三条要点（带依据编号）、缺口数与报告深链接，正文限制在 1200 字以内，超出截断。
事实原文、证据句与完整八节仍在报告与页面里；推送不额外生成事实，也不改写判断。

## 六、竞品追踪报告（五节）

1. **本期事实**：编号 `H{家序}-F{序}`，逐条带证据句与原文。
2. **横向对比**：8 个事件维度 × 各公司矩阵。
   - 单元格是**本期该维度的事实条数**，不是周环比；
   - 行只在至少一家有事实时出现，空维度不占行；
   - 我方（非上市主体）列用自述档案，标记 `我方`，不参与「谁最活跃」排序。
3. **判断**：必须挂事实编号；某家事实不足 3 条时只写「不足以判断趋势」。
4. **建议**：可执行的跟进动作。
5. **待验证与数据缺口**：覆盖不足、跨周趋势需要连续 3 期以上。

竞品追踪报告不提供断点续跑：它由多家子运行组成（单家 24 小时内复用），
重跑比拼接半成品更可靠。

## 七、指标与专题（四段）

指标来源：公开定期报告（营业收入、归母净利润、毛利率、毛利额、经营现金流）
与主营构成（按产品 / 按地区）。

分析类型按条件自动选择：

- 毛利率同比变动绝对值 ≥ 0.5 个百分点 → 「毛利率变动归因」
- 否则 → 「收入增长来源」
- 显式指定时可用「综合体检」

归因拆成两部分：单位盈利效应（各业务自身毛利率变化）与结构效应（业务占比迁移），
残差单独列出，不强行解释。

专题按四段成稿：**事实 → 判断 → 建议 → 待验证与缺口**。

内部指标（资源利用率、均价、补贴确认收入）不进指标列表，只在缺口里列出
需要的内部数据（业务台账、订单与成本记录、政府补助台账），不编数字。

取数限制：白名单指标 × 报告期，不开放自由 SQL。缓存 30 分钟（失败缓存 2 分钟）。

## 八、政策公告

抽取字段：发文机关、文号、发布日期、支持标准、申报截止、适用地区、产业方向。

四类异常：

| 异常 | 含义 | 处理 |
|---|---|---|
| 解析失败 | 无文本层、格式不支持、非公告文本 | 进异常清单，给补材料建议 |
| 字段缺失 | 原文未出现该字段 | 单元格留空并说明原因 |
| 置信度不足 | 区间值、表述模糊 | 自动转人工复核 |
| 需复核 | 规则命中但存在歧义 | 标记后由人确认 |

确认与修正全部写审计（谁、何时、哪个字段、改前改后），原值保留不覆盖。

## 九、运行治理语义

- **取消**：在步骤边界停止，状态记 `cancelled`，已落库材料保留。
- **续跑**：从最近检查点（第 1–4 步）恢复，已完成的采集/解析/抽取不重做。
- **定时**：只在 serve 进程存活期间触发；停机期间错过的时点不补跑。
- **审计**：只追加不覆盖；确认、修正、模型配置、调度、技能执行都留痕。

## 十、设计约束（不可让步）

1. 没有证据句，就不产事实。
2. 缺失就留空，不用推测值填充。
3. 事实和判断在结构上分开。
4. 单份失败不阻断整批。
5. 置信度是算出来的，不是拍的。
6. 只做产业情报：不提供股价、涨跌幅、估值与买卖建议。
7. 模型只能改写语气，不得改动数字、单位与引用；口径冲突必须显式标记，不能合并抹平。
